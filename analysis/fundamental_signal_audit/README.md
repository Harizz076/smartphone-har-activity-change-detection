# Fundamental raw-signal audit

This analysis starts below the classifier level. Its purpose is to establish
which data can legitimately support continuous change detection before choosing
a GLRT distribution, feature set, or threshold.

## Questions asked

1. Are consecutive rows consecutive in time?
2. Does the observed sampling interval agree with the documented rate?
3. Is an activity-label switch an observed physical transition, or is there a
   recording gap between the two blocks?
4. What do the raw axes and acceleration magnitude do at admissible switches?
5. Do the simplest summaries—local mean magnitude, magnitude variability, and
   jerk—change visibly?
6. Does a basic Gaussian mean-shift score become stronger or weaker when the
   window is enlarged?
7. Are the examples spread across users and transition types?

The executable analysis is
[`fundamental_signal_audit.py`](../fundamental_signal_audit.py). It preserves the
input files and writes only derived aggregate results and plots.

## What the WISDM file actually is

The local file is **WISDM Activity Prediction v1.1**, not the newer WISDM UCI
ID 507 dataset described in `CODEX.md`. It has accelerometer x/y/z only—no
gyroscope—and six activities for 36 masked users.

Measured from the local file:

- 1,086,475 valid records were parsed; 11,734 record fragments were malformed.
- The median positive within-user interval is 0.049988 s, consistent with the
  documented 20 Hz rate.
- There are 54,829 non-positive within-user timestamp steps. Therefore file
  row order alone is not a globally continuous timeline.
- Of 346 adjacent label changes, only 16 have a positive time gap no larger
  than 0.5 s.
- Those 16 cases are only upstairs↔downstairs switches and come from users 6,
  14, and 15. Eight retain regular timing for at least 1.5 s on both sides.

Consequently, WISDM v1.1 can supply a small exploratory check for stair-direction
switches, but it cannot be the primary event-level benchmark for general
continuous transitions.

  performs the essential negative-control check. With 0.5 s on each side, the

  2/12 labeled switches exceed the control 95th percentile. A raw mean shift is

## The simple GLRT calculation used in the window check

For a supplied candidate boundary, take `n1` scalar samples before it and `n2`
after it, with `N = n1 + n2`. Under the null, all samples have one unknown
Gaussian mean and variance. Under the alternative, each side has its own mean
while the two sides share an unknown variance. Define

\[
\mathrm{SSE}_0=\sum_{i=1}^{N}(x_i-\bar x)^2,
\qquad
\mathrm{SSE}_1=
\sum_{i=1}^{n_1}(x_i-\bar x_1)^2+
\sum_{i=n_1+1}^{N}(x_i-\bar x_2)^2.
\]

Maximizing the likelihood under each hypothesis gives
\(\widehat\sigma_0^2=\mathrm{SSE}_0/N\) and
\(\widehat\sigma_1^2=\mathrm{SSE}_1/N\). Therefore the exact fixed-split
unknown-variance GLRT statistic is

\[
2\log\Lambda = N\log\left(\frac{\mathrm{SSE}_0}{\mathrm{SSE}_1}\right).
\]

This is a GLRT because the unknown means and variance are replaced by their
maximum-likelihood estimates separately under the one-mean and two-mean hypotheses. In
this audit the supplied label locates the split only for diagnosis. A deployable
detector must scan candidate split points without labels, maximize the score,
and calibrate the resulting maximum on validation streams.

## What this changes from the previous analysis

The earlier `analysis/plots` work remains useful for showing representative
packaged UCI HAR windows, feature correlation, one valid WISDM boundary, and
strong autocorrelation caused by overlapping windows. This audit adds the
checks that were missing:

- it distinguishes continuous boundaries from gaps;
- it reports timestamp failures and usable-event coverage;
- it plots several admissible raw neighborhoods;
- it tests several window sizes with the actual GLRT-scale statistic; and
- it explicitly identifies WISDM v1.1 as accelerometer-only secondary data.

Because this repository intentionally retains only its original UCI HAR and
WISDM datasets, the continuous detector remains a tested generic algorithm.
WISDM's recording gaps prevent a broad event-level transition benchmark, and
the packaged UCI HAR windows must not be stitched into a false continuous
stream. This limitation is preferable to reporting an invalid transition
evaluation.
